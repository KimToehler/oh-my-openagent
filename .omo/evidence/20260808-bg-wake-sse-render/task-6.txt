WHAT WAS TESTED
Commit 5113f9124 made the parent-wake REPLY path requeue on an "already-delivered" coalesce instead of
recording the wake as sent, bounded by MAX_COALESCE_REQUEUE_ATTEMPTS = 3 with a 2000ms backoff. That opens a
new window where a shouldReply wake is still owed AFTER the task completed. Two new cases were added to the
existing retention-guard suite:

  Case A "#given a wake requeued by an already-delivered coalesce #when the cleanup timer fires #then the task
  stays retrievable across the retry window"
    Drives the real BackgroundManager: queues a shouldReply wake via notifyParentSession, then replays the
    dispatch path's discarded-coalesce branch (delete pending -> bump coalesceRequeueCount -> pendingQueue
    .requeueWake) and fires the real completion cleanup timer inside that window, twice.

  Case B "#given the coalesce requeue cap is exhausted while the wake is still owed #when cleanup keeps firing
  #then the task is removed instead of pinned forever"
    Burns all MAX_COALESCE_REQUEUE_ATTEMPTS requeues, then replays the post-cap branch (record as dispatched
    rather than requeue), then keeps firing the real cleanup timer with nothing ever consuming the wake.

The fixture style matches the existing file: same createManager/createTask/installFakeTimers harness, same
Reflect.get accessors, same notifyParentSessionForTest entry point. No new harness was invented. No existing
case was weakened, rewritten, skipped, or deleted. No `as any` / `@ts-ignore` / `@ts-expect-error`.

WHY IT IS ENOUGH
The two cases pin both directions of the new window on the real BackgroundManager cleanup timer: retention
holds while a coalesce retry still owes a reply, and retention terminates once the retry budget is spent. The
mutation proof shows each direction fails when its governing production branch is disabled, so neither
assertion is vacuous. Residual risk: the tests replay the dispatch path's requeue and post-cap branches
through the pending queue and dispatched tracker rather than driving sendParentWakePrompt end to end; that end
to end behavior is already pinned by parent-wake-coalesce-requeue.test.ts (added in 5113f9124).
