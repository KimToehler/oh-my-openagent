== DEFECT ==
Old: MAX_COALESCE_REQUEUE_ATTEMPTS=3, COALESCE_REQUEUE_FLUSH_DELAY_MS=2000 (hardcoded).
Budget = 3 * 2000 = 6000ms < DEFAULT_PROMPT_SEMANTIC_DEDUPE_HOLD_MS = 15000ms.
Hold never refreshed on coalesce, so every requeue coalesced, cap exhausted
inside the hold, wake recorded as dispatched without reaching client.

== FIX (derived, not hardcoded) ==
COALESCE_REQUEUE_FLUSH_DELAY_MS = ceil((DEFAULT_PROMPT_SEMANTIC_DEDUPE_HOLD_MS
  + DEFAULT_PROMPT_ASYNC_POST_DISPATCH_HOLD_MS) / MAX_COALESCE_REQUEUE_ATTEMPTS)
  = ceil((15000 + 2000) / 3) = ceil(5666.67) = 5667ms

== ARITHMETIC: INVARIANT NOW HOLDS ==
3 * 5667 = 17001 >= 15000  (budget >= hold, with 2000ms post-dispatch-hold slack)
Actual worst-case timeline: record written at t0; first coalesce observed >= t0+2001;
retries at +5667 each: t0+2001+5667=7668 (coalesce, count=1), +5667=13335 (coalesce, count=2),
+5667=19002 > 15000 -> real dispatch. Budget survives the hold by construction.
Because delay is DERIVED from the imported hold constant, any future edit to
timing.ts re-derives the delay; the invariant cannot silently drift.
