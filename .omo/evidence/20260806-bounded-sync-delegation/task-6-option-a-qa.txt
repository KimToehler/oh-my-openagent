  DEPLOYMENT CONSIDERATION (real, and worth stating plainly): these changes are
  text baked into the bundle. Any consumer running the PUBLISHED package, or a
  local dist, keeps the OLD wording until `bun run build` regenerates

  packages/omo-opencode/src/shared/dist-bundle-prompt-content.test.ts, which
  asserts prompt markdown is inlined into dist - but that test SKIPS when dist
  is absent and only checks fixed signature strings, not this specific reword.
  Nothing in the source-only change is broken; it simply is not live in a dist
  until a build runs. Publishing runs a build, so shipping is unaffected.

3. HOW THE RUN WAS DRIVEN
-------------------------
Hermetic provider: the BUNDLED fake server, no real API call, no credentials:
  .agents/skills/opencode-qa/scripts/lib/fake-openai-server.mjs

A thin PASSIVE recording proxy sits in front of it (/tmp/omo-qa-t6/record-proxy.mjs).
It appends each upstream request body to a JSONL tape and forwards the request
verbatim, streaming the SSE response back unchanged. It NEVER synthesizes a
model response - the bundled fake server remains the only thing answering. The
tape is how the model-visible tool description was captured (section 4).

Prompt "Run the split probe" is the bundled fake server's scripted branch
(lib/fake-openai-branches.mjs) that deterministically emits a `task` tool call,
then a `bash` hold, then finishes. That makes the delegation deterministic
instead of hoping a fake model improvises one.

  $ opencode run "Run the split probe" --format json > task-6-run.jsonl

TIMEOUT / HUNG-COMMAND BOUND: macOS has neither `timeout` nor `gtimeout` on this
machine (verified: `which timeout gtimeout` -> not found), so the driver
implements an explicit watchdog: a background `sleep 180` that SIGKILLs the
`opencode run` pid if it is still alive after 180 s, then is itself killed on the
normal path. Bound used: 180 seconds. The watchdog DID NOT fire - the run
finished in roughly 11 s (fake-llm log: first call 13:56:40.725, last
13:56:51.223). No `watchdog.txt` marker was written.

5. SCOPE LIMITATION - READ THIS BEFORE CITING THIS EVIDENCE
------------------------------------------------------------
This evidence proves EXACTLY TWO things and nothing more:
  (a) the `task` tool still functions end to end after the reword
  (b) the new wording is what actually ships to the model

It does NOT prove, and MUST NOT be cited as proving, anything about which mode
the model CHOOSES. A single run is statistically meaningless for model behavior.
Claiming "the model now backgrounds more" from one sample would be false
evidence. Establishing a behavioral claim would need a controlled A/B with many
samples per arm against a real model, which is out of scope for todo 6 and was
not done.

ANECDOTAL, EXPLICITLY NOT PROOF: the observed call carried
run_in_background=true. This is NOT a model choice - the bundled fake provider
emits that argument from a hardcoded script
(.agents/skills/opencode-qa/scripts/lib/fake-openai-server.mjs, the
"parent-tool-call" branch). It says nothing whatsoever about real model
behavior, and is recorded only so a reader does not mistake it for a signal.
