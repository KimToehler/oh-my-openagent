SECTION 5 - FINDINGS SUMMARY
================================================================================
F1 (documented behavior, not a defect) The adopted child's RESULT is delivered
   BY HANDLE, not by value. The parent gets "[BACKGROUND TASK COMPLETED]" plus
   the bg id and an explicit instruction to call background_output. The child's
   text never appears inline in the parent transcript. Identical to the existing
   run_in_background=true contract. Prior QA's biggest open question is now
   answered: the result is NOT lost, but it is NOT auto-inlined either.

   be lost if the parent's turn ends before the debounce flushes (T13). Control
   test T14 reproduces it with run_in_background=true and no adoption. Out of
   scope for this change; worth a separate issue.
F3 (cosmetic) background_output on an adopted task reports "Duration | 0s"
   (startedAt reset at adoption discards the ~60s already spent) and
   "Original Prompt: [already prompted]" (the adoption sentinel is user-visible).

   tool-registry-core-tools.ts:68 `?? 600_000`; timing.ts defaults to Infinity.
   Correct for the shipped path, fragile for any other construction site.
F5 (pre-existing, schema-wide) A mistyped config key such as
   syncWallclockTimeoutMs is silently ignored, so a typo yields the default.
