# Bounded sync delegation blocker fixes

## Findings and changes

1. **Shared wall-clock budget across fallback retries.**
   - Cause: `pollSyncSession()` created its start timestamp per poll invocation, while `runSyncTaskLoop()` retries after fallback.
   - Change: `runSyncTaskLoop()` computes one `wallClockDeadline` before its retry loop and supplies it to every poll attempt. `pollSyncSession()` compares `Date.now()` with that deadline. Inactivity tracking remains local to each poll attempt.

2. **Unbounded sync continuation.**
   - Cause: `executeSyncContinuation()` did not pass configured wall-clock timing to the shared poller, leaving its `Infinity` default active.
   - Change: continuation computes same absolute deadline and passes it to `pollSyncSession()`.

3. **Continuation yield ownership race (#5112 class).**
   - Choice: **option (a), adoption**. On a continuation `wall_clock_yield`, `executeSyncContinuation()` calls `manager.adoptRunningSession()`, sets `yieldedToBackground` only after successful adoption, and returns its `bg_...` handle. Cleanup skips handback marking/abort only after ownership transfer. Every non-adopted exit now marks `handedBackSyncSessions` and sends abort, so no live unmarked child can escape.
   - Why: preserves child work and matches working `sync-task.ts` adoption semantics. Comment records ownership rule.
