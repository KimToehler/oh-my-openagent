## WHAT WAS TESTED
The 8 Atlas prompt markdown variants under packages/prompts-core/prompts/atlas/
are the runtime source of truth (packages/prompts-core/src/atlas-prompts.ts
imports each .md via Bun's text loader; resolveVariant() picks one per model and
loadPromptSync() returns its body). Three steering patterns were changed in every
one of the 8 files:
  P1  exploration-vs-task-execution guidance: task execution may now be
      backgrounded, and that is the preferred default; sync is reserved for when
      the parent's very next step consumes the result.
  P2  the NEVER-list entry forbidding run_in_background=true for task execution
      was deleted (it sits under a NEVER heading, so deletion is minimal+correct).
  P3  a backgrounded category= delegation example was added next to the existing
      foreground example so the model has a template for both.

Surfaces driven: per-file grep (BEFORE/AFTER), backtick-tolerant regex gate,
per-file three-pattern audit, `bun test packages/prompts-core/`,
`bun run typecheck`, and a throwaway bun script that calls the real
loadPromptSync()/resolveVariant() runtime path and asserts on the RESOLVED
prompt string a live agent would receive.

## WHAT WAS OBSERVED
- BEFORE: all 8 files carried the restrictive guidance. The plain-phrase regex
  matched only 6 lines across 5 files plus glm.md's "implementation tasks"
  wording; kimi-k2-7.md and kimi-k3.md hid theirs inside a single-line inline
  NEVER paragraph. Both forms are captured in the RED section below.
- AFTER: the backtick-tolerant regex returns ZERO matches; the inline-clause
  regex returns ZERO matches; every one of the 8 files still mentions
  run_in_background (counts 8..14); the per-file audit shows P1 present, P2
  leftover=0, and P3 present for each of the 8 individually.
- `bun test packages/prompts-core/` -> 26 pass, 0 fail, exit 0.
- `bun run typecheck` -> exit 0.
- Resolved-prompt QA -> exit 0 for both the default variant (claude-sonnet-4-5,
  19941 chars) and the glm variant (glm-4.6, 17131 chars): permissive guidance
  present, backgrounded category example present, zero leftover NEVER entries,
  and the background-collection mechanics (background_output(task_id="bg_...")
  and the background_cancel(all=true) warning) still intact.

## WHY IT IS ENOUGH
This is prompt text with no unit-test seam, so the failing-first proof is the
captured BEFORE state showing the restrictive guidance present in all 8 files.
The binary observable is the RESOLVED runtime prompt: the QA script goes through
the same resolveVariant()+loadPromptSync() path the plugin uses, so what it
prints is what a real agent receives. Two different model variants were resolved,
one of them (glm) from the group with divergent wording. The per-file
three-pattern audit rules out a false pass from the naive regex, which by itself
would have missed glm.md, kimi-k2-7.md and kimi-k3.md.

  scripts exercise more directly than the resolved-prompt path used here. No

  at BUILD time, so a `bun run build` is required before a packaged dist picks
  the new text up. That regeneration is explicitly OUT OF SCOPE for this todo
  (see stale_state below) and no build beyond the listed verification commands
  was executed.
- No secrets, tokens, env dumps or auth headers appear in any captured output.

  packages/omo-senpi/plugin/extensions/omo-member.js,
