FIX 1: Root-Descendant Accounting Balance
------------------------------------------
FINDING: AdoptRunningSessionInput lacked explicit tracking of whether a reservation had already been made upstream. In sync-continuation.ts, the adoption path called `unregisterRootDescendant` without a prior `registerRootDescendant`, causing a double-decrement of the descendant counter. This corrupted root-descendant accounting when a continuation branch was adopted into a background session.

  - packages/omo-opencode/src/tools/delegate-task/sync-continuation.ts:210

IMPLEMENTATION:
  1. types.ts: Added REQUIRED field `rootDescendantAlreadyReserved: boolean` to AdoptRunningSessionInput.
  2. sync-task.ts:151: Passes `rootDescendantAlreadyReserved: true` because reserveSyncSubagentSpawn already committed the reservation.
  3. sync-continuation.ts:210: Passes `rootDescendantAlreadyReserved: false` because the continuation path does not reserve upstream.
  4. manager.ts:671-673: Calls `registerRootDescendant()` only when the flag is false. This ensures the later `unregisterRootDescendant` in `tryCompleteTask` is always balanced—no more double-decrements.

FIX 2: Adoption Idempotency
---------------------------
FINDING: Two separate yield sites (`sync-task` and `sync-continuation`) could both enqueue the same child session as a background task during concurrent or retry scenarios. Each would independently register the child, causing duplicate parent-wake notifications and a double root-count decrement when the task completed.

FILES:
  - packages/omo-opencode/src/features/background-agent/manager.ts:665-669
  - packages/omo-opencode/src/features/background-agent/manager.adopt.test.ts

IMPLEMENTATION:
  1. manager.ts:665-669: Added idempotency guard. Before processing the adoption, scan `this.tasks` for an existing non-terminal task owning the same `input.sessionId`.
  2. If found, return that existing task immediately—do not re-register.
  3. Critically, this guard sits BEFORE the `registerRootDescendant` call at line 671, so a repeat adoption cannot double-register.
  4. Uses the file's existing `TERMINAL_BACKGROUND_TASK_STATUSES` set (immutable list of terminal states).

EVIDENCE: manager.adopt.test.ts covers the idempotency path with a red/green test; verified by delegate-task suite delta (499 → 500 pass).


FIX 3: Abort Beats Yield
------------------------
FINDING: In sync-session-poller.ts, the abort check and the wall-clock deadline check raced each other. When both conditions were true at a boundary, the order of evaluation determined behavior. An explicit user ESC (abort) could lose the race to the deadline check and the child would be yielded to background instead of aborted, contradicting explicit user intent.

FILES:
  - packages/omo-opencode/src/tools/delegate-task/sync-session-poller.ts:119
  - packages/omo-opencode/src/tools/delegate-task/sync-session-poller.wall-clock.test.ts

IMPLEMENTATION:
  1. sync-session-poller.ts:119: Added abort check (`ctx.abort?.aborted`) BEFORE the wall-clock deadline check at line 155.
  2. This ensures user intent (ESC) is honored first; only if not aborted do we evaluate the deadline.
  3. Matches user expectation: abort is a synchronous, explicit signal that takes precedence over background deadlines.

EVIDENCE: Wall-clock test suite covers the abort-vs-deadline race; verified by test suite deltas.
