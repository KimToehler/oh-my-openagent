ADDITIONAL isolation applied by the driver, beyond qa-sandbox.sh:
  HOME = <root>/home

  Reason (important, and NOT covered by qa-sandbox.sh): the omo config loader
  resolves the USER config layer from HOME, not from XDG_CONFIG_HOME. See
  packages/omo-config-core/src/loader/paths.ts:
     resolveUserOmoConfigDirectory() -> join(resolveHomeDir(env), ".omo")
     resolveHomeDir() -> env.HOME ?? env.USERPROFILE
  With only qa-sandbox.sh sourced, the host's real ~/.omo/omo.jsonc would still
  have been loaded into the sandboxed run and would have routed every agent at
  the real `onara/*` models, defeating the hermetic fake provider. Sandboxing
  HOME closes that leak. The host's ~/.omo/omo.jsonc was READ-ONLY inspected
  and never modified.

  $HOME/.opencode/bin was symlinked into the sandbox home (the same trick
  oqa_preserve_home_opencode_bin uses in the opencode-qa common.sh harness) so
  the opencode launcher still resolves after HOME is rewritten.
