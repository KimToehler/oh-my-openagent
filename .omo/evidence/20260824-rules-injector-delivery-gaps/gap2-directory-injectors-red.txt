Surface driven: the `tool.execute.after` handler returned by
`createDirectoryAgentsInjectorHook` and `createDirectoryReadmeInjectorHook`,
invoked directly with a real temp project root containing a nested
`src/AGENTS.md` / `src/README.md` beside the read file.

Behavior it was meant to prove: an MCP-served read tool name
(`lean-ctx_ctx_read`, `mcp__server__read`) must trigger the directory-context

(`lean-ctx_ctx_shell`) must not.

WHY IT IS ENOUGH
----------------
The 4 failures are exactly the MCP-prefixed read cases, one pair per hook, and
they fail for the right reason: the injector never ran, so `output.output` is
still the untouched `"base output"` fixture rather than a partially built or
malformed block. The 4 passes in the same run are the regression pins - native
`read` still injects, and `lean-ctx_ctx_shell` still does not - which proves the
new tests are not simply asserting that the hook does nothing, and that the
forthcoming fix must not widen matching to non-read tools.

WHAT WAS OMITTED
----------------
Nothing redacted. The run touches no credentials, no network, and no real user
state: each test builds its own `mktemp` project root, mocks the session storage
module in-memory, and removes the temp root in `afterEach`.
